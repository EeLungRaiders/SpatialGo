2. 產品鎖定（不得改掉）
============================================================

立體空間圍棋，不是平面盤加 z，不是平面 Go 的 3D 視圖。

- 只做 4×4×4；board[z][y][x]；SIZE=4
- 六鄰資料可先寫進 DIRS；P1 play 只拒越界與佔格
- 只有 3D：透明立方格 + 3D 棋子；沒有平面棋盤樣子；沒有 2D／3D 切換
- 規則在瀏覽器 JS；ProgramGo_SV 純殼
- 專頁 /gogame/gogame.htm 唯一遊玩面；殼 GoBoard 只開專頁

沿用
- extras：同一 TGeoPainter；高 numfaces／numnodes；暫時 wrap drawExtraShape 後立刻還原
- Reset：相機歸位後高上限再掛子；禁止常駐 drawExtraShape；禁止亂改 select_in_view
- 加子／Undo 同一條依 state 全量重建 extras
- 不要每手 nvidia-smi；不要裸 TGeoBBox 當唯一 JSROOT.draw
- 不要假設 THREE.BoxGeometry 是 constructor

不要（P1 與尚未批准）
- 提子、自殺禁、劫、Pass／Resign 當可玩流程
- SGF、計分、死子、領地
- 切層 2D、層選 UI、一次畫多層 2D
- 刪除 board2d.js／sgf.js／scoring.js
- 新 C++ class、改 SetSV 邊界、套遊戲映像
- 射線 ∩ 平面 z=0 當 picking
- 木質 slab 當棋盤
- 為「以後可能有 2D」去實作切層

4. Apply 時一併鎖定（01_1 §3）
============================================================

1. worldOf(x,y,z) 只定義一次；格線、空點淡標記、球心、picking 全用它。
   worldOf(x,y,z) = (x-1.5, y-1.5, z-1.5)；CELL=1；球心在格點；R≈0.32。
2. 相機 up 軸／framing 沿用現況 board3d 的 painter，不要另發明 Y-up／Z-up。
3. 建議做 GoGame.cpp AutoLoad 拿掉 board2d、sgf／scoring cases
   （以及專頁不載的平面測試），避免開殼誤跑平面測試。
   不改 SetSV.C；不新開 class。對 thttpserver-integration：只動 EnsureAutoLoad 字串。
4. getGroup／getLiberties 若 P1 就改六鄰：可以；不要順便把提子／自殺／劫當 P1 必過。
5. 空點 TPolyMarker3D 畫不出來不卡關；picking 主方案不依賴它。
6. P1 可繼續 clearDom + 全量重建 extras（64 子）；不要做第二套增量 mesh 真相源。

Picking（已選主方案）
- 相機射線（Raycaster 或現況 rayFromCameraNdc）對 64 格點吸附
- dist ≤ 0.45；平手取較小 t（靠鏡頭）
- 回傳 {x,y,z}；不依賴 BoxGeometry；不改 JSROOT 核心
- 備案本 Phase 不做（除非主方案在實機系統性偏格；P1 apply 不要先做備案）

呈現
- 先畫立方體 12 邊（完整 AABB），再三軸格線 TPolyLine3D
- 空點極淡 TPolyMarker3D（失敗不卡關）
- 子：TEveGeoShapeExtract + TGeoSphere extras；建樹 z,y,x；高 numfaces
- 禁止 J.draw(stones) 當第二個 main

Rules P1
- play(state,x,y,z)／isLegal：只拒越界與非空
- history 含 z；Undo 走 State.undo + 3D redraw
- UI：Pass／Resign 隱藏或 disabled
